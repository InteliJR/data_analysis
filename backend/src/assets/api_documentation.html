🗄️ Modelagem do Banco de Dados

O diagrama abaixo representa a estrutura lógica do banco de dados do sistema, mostrando todas as entidades, seus relacionamentos e principais campos.

📝 Principais Entidades:
  • User: Usuários do sistema com diferentes roles (ADMIN, COMERCIAL, LOGISTICA, IMPOSTO)
  • Product: Produtos finais com composição de matérias-primas
  • RawMaterial: Matérias-primas com múltiplas localizações de fornecimento
  • Location: Localizações/fornecedores com preços específicos
  • FreightTax / RawMaterialTax: Impostos aplicados a fretes e matérias-primas
  • Freight: Fretes com custos e impostos associados
  • FixedCost: Custos fixos para cálculo de overhead
  • ProductGroup: Agrupamento de produtos para análise

🌐 Endpoint Público para Clientes (EXTERNAL_API_TOKEN)

⚠️ Autenticação Especial: Este endpoint é destinado a clientes externos para popular o banco de dados. Requer o token EXTERNAL_API_TOKEN configurado nas variáveis de ambiente.

POST /products/full-create

Descrição: Endpoint completo para criação de produto com todas as dependências (matérias-primas, localizações, impostos e fretes). Permite que o cliente crie produtos complexos em uma única requisição.

Autenticação:

Authorization: Bearer <EXTERNAL_API_TOKEN>
📝 Importante: O valor do EXTERNAL_API_TOKEN deve ser configurado no arquivo .env do servidor e mantido em segredo.

Request Body Completo:

{

  "name": "Nome do Produto",
  "description": "Descrição do produto",
  "productGroupId": "uuid-do-grupo", // opcional
  "fixedCostId": "uuid-do-custo-fixo", // opcional
  "freightIds": ["uuid-frete-1", "uuid-frete-2"], // opcional
  "stateUf": "SP", // opcional
  "city": "São Paulo", // opcional
  
  "rawMaterials": [
    {
      "code": "MP-001",
      "name": "Resina Poliéster",
      "description": "Resina de alta qualidade",
      "measurementUnit": "KG", // KG, G, L, ML, M, CM, UN, CX, PC
      "inputGroup": "Resinas", // opcional
      "paymentTerm": 30, // dias
      
      "locations": [
        {
          // Opção 1: Referenciar localização existente
          "locationId": "uuid-da-localizacao",
          
          // Opção 2: Criar nova localização
          "location": {
            "name": "Fornecedor ABC",
            "stateUf": "SP",
            "city": "São Paulo",
            "country": "BR" // opcional, padrão: BR
          },
          
          "acquisitionPrice": 25.50,
          "currency": "BRL", // BRL, USD, EUR
          "priceConvertedBrl": 25.50, // opcional, calculado se moeda diferente
          "additionalCost": 2.30, // opcional
          
          "freightIds": ["uuid-frete-1"], // opcional
          
          "taxes": [
            {
              // Opção 1: Referenciar imposto existente
              "taxId": "uuid-do-imposto",
              
              // Opção 2: Criar novo imposto inline
              "name": "ICMS",
              "rate": 12.0,
              "recoverable": false
            }
          ]
        }
      ]
    }
  ],
  
  "composition": [
    {
      "rawMaterialCode": "MP-001", // deve corresponder ao código acima
      "quantity": 2.5,

    }
  ],
  
  "pricing": { // opcional, apenas informativo
    "additionalCosts": 5.0,
    "margin": 15.0
  },
  
  "measurementUnit": "UN", // opcional
  "paymentTerm": 30 // opcional
}

Fluxo de Criação:

  1. Validação do Token: Sistema valida o EXTERNAL_API_TOKEN
  2. Criação de Localizações: Se location for fornecido, cria nova localização; se locationId, reutiliza existente
  3. Criação de Impostos: Se name e rate fornecidos, cria novos impostos; se taxId, reutiliza existentes
  4. Criação de Matérias-Primas: Cria ou atualiza matérias-primas com suas localizações e impostos
  5. Criação da Composição: Vincula matérias-primas ao produto
  6. Cálculo do Preço: Calcula automaticamente o preço baseado nas matérias-primas, impostos, fretes e custos fixos
  7. Criação do Produto: Salva produto com todas as informações calculadas

Códigos de Status:

Código Descrição
201 Produto criado com sucesso
400 Erro de validação no payload (campos obrigatórios faltando ou formato inválido)
401 Token ausente ou inválido
409 Produto com este código já existe
500 Erro interno do servidor

Exemplo de Erro (400 Bad Request):

{
  "statusCode": 400,
  "message": [
    "code deve ser uma string não vazia",
    "rawMaterials deve conter ao menos 1 item",
    "composition[0].quantity deve ser maior que 0"
  ],
  "error": "Bad Request"
}
💡 Dicas de Uso:
  • Use locationId e taxId para reutilizar entidades existentes
  • Crie novas entidades inline quando necessário com location e detalhes do imposto
  • O campo composition deve referenciar os códigos das matérias-primas enviadas no mesmo payload
  • Unidades de medida: KG, G, L, ML, M, CM, UN, CX, PC
  • Moedas suportadas: BRL, USD, EUR

🔐 Autenticação

A maioria dos endpoints requer autenticação via JWT Bearer Token.

POST /auth/register

Descrição: Registrar novo usuário (requer ativação por ADMIN)

{
  "email": "usuario@exemplo.com",
  "name": "Nome do Usuário",
  "password": "senha123",
  "role": "COMERCIAL" // opcional: ADMIN, COMERCIAL, LOGISTICA, IMPOSTO
}

POST /auth/login

Descrição: Fazer login e obter tokens

{
  "email": "usuario@exemplo.com",
  "password": "senha123"
}

Response:

{
  "accessToken": "eyJhbGc...",
  "refreshToken": "eyJhbGc...",
  "user": {
    "id": "uuid",
    "email": "usuario@exemplo.com",
    "name": "Nome",
    "role": "COMERCIAL"
  }
}

POST /auth/refresh

Descrição: Renovar access token

{ "refreshToken": "eyJhbGc..." }

POST /auth/logout

Descrição: Fazer logout e invalidar tokens

Requer: JWT no header

{ "refreshToken": "eyJhbGc..." }

GET /auth/me

Descrição: Obter perfil do usuário autenticado

Requer: JWT no header

Query Params: ?page=1&limit=10&search=nome&role=COMERCIAL&isActive=true&sortBy=name&sortOrder=asc

Obter usuário por ID

Obter dados do próprio usuário (qualquer autenticado)

Atualizar usuário (ADMIN)

{
  "name": "Novo Nome",
  "role": "ADMIN",
  "isActive": true,
  "password": "novaSenha123" // opcional
}

PATCH /users/me

Atualizar próprio perfil (qualquer autenticado)

{
  "name": "Novo Nome",
  "email": "novo@email.com", // requer currentPassword
  "currentPassword": "senhaAtual",
  "newPassword": "novaSenha123" // requer currentPassword
}

POST /users/export

Exportar usuários em CSV

{
  "columns": ["name", "email", "role", "isActive", "createdAt"],
  "search": "termo", // opcional
  "role": "COMERCIAL" // opcional

📝 Regras Gerais

Paginação

Todos os endpoints de listagem suportam:

  • page - Número da página (padrão: 1)
  • limit - Itens por página (padrão: 10, máximo: 100)
  • sortBy - Campo para ordenação
  • sortOrder - Direção: asc ou desc

Roles (Perfis)

Role Descrição
ADMIN Acesso total ao sistema
COMERCIAL Gerencia produtos, matérias-primas e grupos
LOGISTICA Gerencia fretes e localizações
IMPOSTO Gerencia impostos

Unidades de Medida

KG, G, L, ML, M, CM, UN, CX, PC

Moedas

BRL, USD, EUR

Códigos de Status HTTP

Código Descrição
200OK - Sucesso
201Created - Recurso criado
400Bad Request - Erro de validação
401Unauthorized - Não autenticado
403Forbidden - Sem permissão
404Not Found - Recurso não encontrado
409Conflict - Conflito (ex: duplicação)
500Internal Server Error - Erro do servidor

Estrutura de Erro

{
  "statusCode": 400,
  "message": "Mensagem de erro ou array de erros",
  "error": "Bad Request"
}
